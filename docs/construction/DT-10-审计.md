## DT-10：第五批审计

状态：在做（2026-11-02）。

### 目的

第五批审计（2026-10-30，审 main `b94ffd8`，报告在审计那边 `round5-desktop.md`）给外壳报了七条：D5-1、D5-2 中，D5-3 到 D5-6 低，D5-7 是提醒。这一步七条都改掉，一条一个提交。审计给的两个红测试照原样放进仓库，改之前红、改之后绿。

### 蓝图改哪几节

- `docs/blueprint/desktop.md`「怎么走」第 6 条（导航不往外交，D5-1）、第 4 条（数据目录只给自己，D5-2）、第 2 条（`PATH` 只认绝对目录，D5-4）、第 14 条（调试口子只在 debug 编译里认，D5-5）、第 15 条（日志轮转、限流，D5-6）；「装在哪」钉流水线那一条（D5-3、D5-7）；「守着它的」跟着改。

### 要拍板的

- D5-1 照审计推荐的修法：窗口里看到的非同来源导航一律不开、不交系统浏览器，往外开只走新窗口。备选的限流治标（框里的脚本还是能开第一次），不用。代价：网页里没写 `target=_blank` 的外链在窗口里点了没反应（审计查过钉的网页，没有这样的）。
- D5-5：正式版完全不认 `MIYU_DESKTOP_DEBUG_PORT`。以后要在装好的包上查页面（DT-6 在 Windows 上就是这样查的），得另出一个 debug 编译的程序换上去。

### 不做什么

- 网页那边产物「不许联网」只靠 CSP、挡不住框跳走（审计 D5-1 的附带一条）：网页的事，告诉网页的会话。
- `ci.yml` 里的外部 action 照旧按标签用：它只有读权限，不在这一步动。
- 卸载时删外壳的数据目录：各平台的卸载不归外壳管，只在图纸写明这个目录里有设备令牌。

### 验收

1. 两个红测试 `navigate::tests::audit5_a_navigation_seen_by_the_window_is_not_handed_to_the_browser`、`program::tests::audit5_relative_path_entries_are_not_searched` 改之前红在断言、改之后绿。
2. 每个提交 `cargo fmt --check`、`cargo clippy --all-targets --locked -- -D warnings`、`cargo test --locked` 过；每个 `.rs` 不超过 500 行。
3. 数据目录的权限、日志轮转和限流有单测；`release.yml` 的写法照 YAML 读得通，钉的提交号用 `git ls-remote` 查的。

### 风险

- `release.yml` 拆成两个任务、按提交号钉 action：要等下一次推 `step/` 分支、打 tag 才真跑；附件的名字、发版那一步的 `gh` 要指明仓库（不再 checkout）。
- macOS、Windows 上的导航改动只能等出包手测：Windows 的 WebView2 本来就只给主框架，改了以后主框架里非同来源的导航也只是不开。

### 结果

- D5-1：`navigate::navigation` 非同来源的一律 `Drop`；原来盯着「交系统浏览器」的三个测试改成盯「不开」。红测试改之前红在 `navigate/tests.rs:101`（`https://example.com/leak?n=1` 得到 `Elsewhere`），改之后绿。
- D5-2：新的 `src/folder.rs`，Unix 上建外壳的数据目录、`webview/` 用 0700，本来有的收成 0700；四个单测（新建、建两次、新建的权限、本来 0755 的收紧）。外壳本身没起，WebKitGTK 写出来的文件权限没再实测（审计实测过 0644，目录 0700 以后不相干）。
- D5-3：`release.yml` 拆成 `pack`（`contents: read`，三次 checkout 都 `persist-credentials: false`，钉的版本另传一个 `pins` 附件）和 `release`（只在 `v` tag 上跑，`contents: write`，下附件、`gh` 用 `GH_REPO` 指仓库）；四个外部 action 按提交号钉：`actions/checkout` v7.0.1、`Swatinem/rust-cache` v2.9.3、`actions/upload-artifact` v4.6.2、`actions/download-artifact` v4.3.0（和 upload 同一代），提交号用 `git ls-remote` 查标签、`gh api` 核对过。只用 Python 的 YAML 读过一遍，没真跑；三个平台有一个没打出来，发版整个不建（原来是传一半）。
- D5-4：`program::locate` 只认 `PATH` 里 `is_absolute()` 的目录。红测试改之前红在 `program/tests.rs:180`（交回 `Some("miyu")`），改之后绿。原来的 `the_path_is_searched_in_order` 用的 `/a`、`/b`、`/c` 在 Windows 上不算绝对（没有盘符），改成照临时目录拼。
- D5-5：`window.rs` 读环境变量挪进 `debug_port()`，用 `cfg!(debug_assertions)`：正式版交 `None`（代码照样编进去，不会在 release 里冒出没用到的警告）。`browser_args` 的两个单测照旧。没编正式版去验环境变量被忽略（只差一个 `cfg!`）。
